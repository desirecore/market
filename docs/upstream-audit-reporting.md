# 上游审核与 unhealthy 报告 / Upstream audit and unhealthy reporting

本机制待 PR #354 合并到 main 后生效；本 PR 不自动合并或部署自身。报告不执行上游脚本，也不是运行验收或软件安全认证。

## 审核边界

- **仓库许可 ≠ 安装交付**：按 source.path 或每个 collection child.path 独立检查。MIT 的完整版权、授权及免责通知必须能与声明的主证据对应；vendor/LICENSE 或单行 SPDX 不能替代主项目通知。README/SKILL 内完整等效通知可以通过，不强求文件名 LICENSE。
- 自动证明仅识别所选目录直接包含的 LICENSE/COPYING/NOTICE/README/SKILL 中的完整等效文本；嵌套、改写、其他非标准许可证据可能被保守转人工，不能据此断言不存在合法许可。声明的 NOTICE 未证明交付会阻断；未声明根 NOTICE 的适用性需要人工确认。
- **精确 pin 例外**：旧 pin 接受过的单行 MIT 例外，即使 README 哈希不变，也不自动扩展到新 pin。新 pin 需要独立人工授权；本更新器不产生这种授权，不改变 listing-only 准入状态。
- **版本和双语**：用真实 SKILL frontmatter、明确插件 manifest 作为对应对象的版本证据；根插件版本不强加给所选子目录技能。只提示文案中出现的确切旧插件版本，需人工确认含义，不替换任意数字。同步检查 entry/catalog 的子项语言镜像；英文回退标为历史信息，不伪称已翻译。
- **直接 Git 对象差异**：报告安装范围完整路径差异，不依赖 GitHub compare 的 300 文件截断列表。授权/凭据/配置/网络相关命名的实现文件变化，保守转人工。这是复核提示，不是已证实漏洞，更不是全部行为审核。原有最终 SHA 的实际差异及真人行为审核门禁不变。
- **失败分层**：原流水线实际失败、失败点后的未完成阶段、独立静态发现、人工待审、历史遗留、本次引入分别展示。开发依赖与所选技能运行依赖不混为一谈；YAML 修复后的重新发现不叫新增物理文件。解析器不可靠时不得认定通过。
- **真实回执**：审核失败不生成成功回执；后续目录校验失败时恢复真实旧回执，独立保存失败命令与输出。ZIP/Web/local 的临时物化 Git ID 不暴露为真实来源 pin。

## 自动维护与稳定展示

日程、发布身份、凭据和最终 SHA 合并保护不变。Git 每轮最多审核 5 个新候选，另可只读复审 5 个已有 PR；不修改已有 PR 的内容。ZIP/Web/local 使用同一套保守门禁并输出真实结果。预算之外明确未检查。

Git 提案 coverage、ZIP/Web/local 的 tracked-results 和来源健康结果汇总为中英双语报告；工作流在提案审核之后同步原 upstream-health issue，并保留完整 audit-results 工件。大报告只截断 issue 展示，不截断 JSON 证据或声称省略部分已通过。

托管区为 `<!-- market-upstream-health:begin -->` 到 `<!-- market-upstream-health:end -->`。首次迁移把现有手动双语正文保留为明确标注的历史快照，之后只更新托管区，保留人工前后文。无时间戳/run URL 驱动的每日重复编辑，不发评论；无实质变化不更新。已解决且检查完整才关闭，出现新问题重开同一 issue；不完整、网络未知或未审核的更新不得闭环。原本 listing-only 或未登记版本源本身不是新失效，来源状态另行报告。
