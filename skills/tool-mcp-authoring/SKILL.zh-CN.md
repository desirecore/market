# 自建 Tool 与 MCP

## 选择交付方式

把用户需要的能力实现成可核验、可继续使用的代码和合同。Agent 选择语言、库及实现方式，平台提供原文件工具、执行、发现、审批与运行事实；不要求固定业务流程。

| 用户目标 | 可选承载 |
|---|---|
| 一次诊断、读取或转换 | 在授权工作目录写脚本并执行 |
| 有输入 Schema 的可复用原子操作 | AgentFS 自定义 Tool |
| 多个操作共享设备连接或服务状态 | 自编 MCP Server，接入实际目标 Agent Service |
| 可复用的方法、约定及配套脚本 | Skill；它本身不会登记函数工具 |
| 配置界面、多设备管理、可安装交付 | 应用或插件，可组合既有 Tool/MCP |

先检查已有能力及用户选择。用户明确要求自建时可直接编写，不必先查市场。涉及应用交付时按目录加载应用作者 Skill，作者动作使用 `AppAuthoring`；安装生命周期使用 `AppManage`。

## 使用真实环境与原授权

- 沿用当前任务的 Plan、工作目录及授权；不因创建工具而改审批模式、获取平台 token 或扩大子任务权限。跨 Agent 安装/改配置需要该目标的原授权。
- 探测实际运行时、库、驱动和设备/服务。依赖不存在时按可用的运行时 Skill 或原执行工具准备，记录版本和安装位置。第三方库、设备、托管服务的许可证、部署条件及费用由所选依赖决定；缺少条件时报告具体不可用项。
- 代码和可审阅配置放在获准目录，设备私有参数与凭据留在私有配置或原连接 owner；不写进公共 Skill、命令行、日志或示例。注册连接器不会提供外部硬件、许可证或服务。
- 串口号、波特率、设备地址、网络端点等由实际设备及协议材料确定；配置与参数 Schema 提供 description。读状态和写设备按真实副作用分别声明风险，测试先使用获准的只读操作或模拟端点，不能冒充真机结果。

## 按需读取作者合同

- 原子脚本工具、完整 TOOL.md、登记与发现：读 [AgentFS 工具](references/agentfs-tool.zh-CN.md)。
- 本地或远端 MCP、依赖、连接和共享：读 [MCP 服务](references/mcp-server.zh-CN.md)。
- 保存操作方法时按目录加载 Skill 作者/管理指南；共享 HTTP/MCP 目录时按目录加载服务登记指南。接入自身 MCP 不要求先登记全局目录。

## 核验结果与生命周期

分别记录：源代码和依赖已准备、配置已保存、注册/发现成功、实际调用成功、设备行为已观测、重启恢复已验证。只完成前一项时不承诺后一项。

刷新注册表后按当前工具目录和实际模型声明调用。加载工具不会扩大权限；固定工具上限的子任务或后台 Run 不能靠新建能力绕过原上限。按错误和原上下文选择下一轮、适当执行 Agent 或报告需要的授权，不盲目重复加载。

长期 MQTT 等订阅要有真实进程/服务载体，并明确事件如何通过获准的原调度、Webhook 或其它实际入口触达 Agent。MCP 列表变化通知不是设备业务事件的通用唤醒器；保存配置、一次后台命令或注册 MCP 都不能证明应用重启后仍在监听。若选择调度，使用 `ManageSchedule`，不直接写持久调度文件。

按所选交付核验端口占用、超时、取消、断连/恢复与必要的并发访问；设备写入结果未知时先核实状态再决定是否重试。关闭或移除能力时只处理本次拥有的连接、进程与注册，不停止共享服务。给出实际入口、调用示例和未验证范围，不要求每个简单脚本都打包成应用。
