# 运行服务笔记工作台

需要用户实际选择并可用的 Node.js 运行时。此示例不安装 Node、Docker 或第三方数据库，不向平台注册 MCP。Node 服务只提供固定网页、只读计数分析和当前 TaskHost 运行身份握手；业务笔记使用平台有限 data key，与静态示例采用同一CAS保存约定。

在获授权的材料目录生成release并prepare后，使用原执行工具实际启动 `PORT=<已选择空闲端口> node runtime/server.mjs`。端口需固定在原接受的执行合同，不能靠网页声明任意endpoint。身份由原TaskHost在受控正式spawn时注入：DESIRECORE_APP_RUNTIME_PROOF、DESIRECORE_APP_RELEASE_DIGEST、DESIRECORE_APP_SCOPE_ID、DESIRECORE_APP_RUNTIME_GENERATION。应用不能自报固定PID或伪造proof，不能将proof用于其他API或日志。

调用 `/api/apps/runtime/contracts` 时给真实prepareRef、installationId、terminalId、endpoint.port与identityPath `/.desirecore-app-identity`，以及用户选择的 manual/on-open。纳管读取原accepted-command冻结执行合同；由原执行工具明确停掉此前命令，commit后由原owner启动正式新代际，再核读运行身份和应用功能。原先裸启动的服务在没有managed身份时会明确返回503，它只能帮助开发调试，不能证明正式可信直开。

公开执行环境不接受任意.env。若改造应用需要后端直接读写数据，须使用实际数据owner授予并注入的独立根；缺授权时不写盘，不默认使用cwd或release目录。此教学服务没有后端数据写入，因此不需要APP_DATA_DIR，不持有平台凭据。

停止、更新、失败恢复沿原TaskHost/Run，不重复开第二个后台进程。scope/release/generation改变后旧连接失效；重启须重新取得owner身份与审批事实。端口被占用不接管，不把HTTP200作为运行归属证明。
