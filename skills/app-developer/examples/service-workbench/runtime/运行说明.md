# 运行服务笔记工作台

需要用户实际选择并可用的 Node.js 运行时。此示例不安装 Node、Docker 或第三方数据库，不向平台注册 MCP。Node 服务只提供固定网页、只读计数分析和当前 TaskHost 运行身份握手；业务笔记使用平台有限 data key，与静态示例采用同一CAS保存约定。

在获授权的材料目录生成 release 并 prepare 后，使用原执行工具实际启动 `PORT="${PORT:-32000}" node runtime/server.mjs`，初次默认值须替换为实际空闲端口。保留该默认表达式，不能用写死的 PORT 赋值覆盖 Harness 后续注入的预览端口。端口需固定在原接受的执行合同，不能靠网页声明任意 endpoint。身份由原 TaskHost 在受控正式 spawn 时注入：DESIRECORE_APP_RUNTIME_PROOF、DESIRECORE_APP_RELEASE_DIGEST、DESIRECORE_APP_SCOPE_ID、DESIRECORE_APP_RUNTIME_GENERATION。应用不能自报固定 PID 或伪造 proof，不能将 proof 用于其他 API 或日志。

通过原 `AppManage.runtime_enroll` 的 `owner_request` 给真实 prepareRef、installationId、terminalId、endpoint.port 与 identityPath `/.desirecore-app-identity`，以及用户选择的 manual/on-open。普通 HttpRequest 不自动注入平台凭据，不能读取实例 token 或改 Origin 绕过认证。纳管读取原accepted-command冻结执行合同；由原执行工具明确停掉此前命令，commit后由原owner启动正式新代际，再核读运行身份和应用功能。原先裸启动的服务在没有managed身份时会明确返回503，它只能帮助开发调试，不能证明正式可信直开。

公开执行环境不接受任意.env。若改造应用需要后端直接读写数据，须使用实际数据owner授予并注入的独立根；缺授权时不写盘，不默认使用cwd或release目录。此教学服务没有后端数据写入，因此不需要APP_DATA_DIR，不持有平台凭据。

停止、更新、失败恢复沿原TaskHost/Run，不重复开第二个后台进程。scope/release/generation改变后旧连接失效；重启须重新取得owner身份与审批事实。端口被占用不接管，不把HTTP200作为运行归属证明。

开发时若需要直接看授权源码的修改，可用当前真实 draft、原 source 目录启动的 terminalId 和已固定 prepareRef 通过 `AppManage.development_enroll` 的 `owner_request` 登记原 prepareRef/draft/terminalId/endpoint。它只承接 live 预览，正式发布须另固定 snapshot 并登记正式运行合同；普通读取静态源码的变化不等于框架 dev-server/HMR 协议已经验收。

要将此服务改为 Docker release，须由作者实际选择并验证固定 Node 镜像 RepoDigest、声明全部 imageRefs，容器服务监听 `0.0.0.0` 而宿主只发布 `127.0.0.1`，并沿 AppManage.docker_prepare/docker_enroll 的实际 argv、nonce、CID 和 data mount 核验。当前文件是 native Node 教学样例，不能只改 delivery 类型就声称容器运行通过；镜像及 Docker 许可、安装与运维属于其实际外部 owner。
