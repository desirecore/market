# 服务笔记工作台教学示例

这是可修改的固定网页＋原生Node只读服务，不是正式市场条目。先读本Skill作者接口和runtime/运行说明.md，在真实目标环境按目标组合原 AppManage.prepare_release/runtime_enroll/commit_release 动作，纳管原执行合同、正式发布并核验。缺TaskHost owner或真实身份时保持不可用，不能重标为静态网页来绕过。

笔记仍通过应用桥的notes key持久化，用户、实例和预览各有独立scope；Node端不写个人数据或固定程序目录。网页可在本源 `/api/summary?count=<当前笔记条数>` 请求只读统计；这个能力不使用平台token，也不接收任意文件路径或SQL。

与Agent协作、保存超时恢复及更新/data合同遵循静态示例的相同约定。应用是否能运行与外部Node环境、原执行owner和当前用户授权有关。包不附带用户数据库、.env、平台身份或proof值。分发必须取得真实不可变来源和目录审阅回执；第二用户安装需独立环境，不共享开发者进程或业务数据。

工作查询保留原 agentId 和 clientRequestId；只有 readWork 返回的真实 Task 成果 locator 才可交 openResource 定位，navigation-requested 不等于文件正文已打开。当前 controlWork 只按 availableActions 支持 abort；未关联 Task 的工作成果列表可以为空，不凭 UI 编造 Task。

用户可显式选择“在这台设备记住所选位置”。示例 viewStateContract 只允许 selection 键并限制 1024 字节，不保存笔记正文；需实际 saveViewState grant，设备保存保持原 mutationId、expectedRevision 和正文。能力缺失时保持业务数据与视图偏好分别报告，预览不借正式设备状态。

用户要求分发时，用原 AppManage.export_release 的 owner_request 显式导出全部 payload 与 app-release.json；另给原工具真实写权限内的 export_file_ref，首次 expected_absent:true，已有目标用原 expected_etag。返回 archiveFile 的实际 fileRef/sha256/size/etag，核验 sha256/size 与 export 的 archiveDigest/size 一致后交原授权上传工具。取得真实固定来源再用 distribution_prepare 的 owner_request，registryRepoId 从 authoring_capabilities.registryTargetIds 选本次实际目标，生成三文件草稿；它不上传、不提交目录，也不改变个人安装身份。普通 HTTP 不自动注入平台凭据，不能读取实例 token 或绕过认证。
